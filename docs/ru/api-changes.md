# Что изменилось в API · ветка `feature/api`

Справка для того, кто встраивается в `ragu.api` или дорабатывает его. Полный
контракт — [`api.md`](api.md) и [`../openapi.json`](../openapi.json); здесь
только дельта и то, что из неё следует для потребителя.

Состояние: 55 операций, 58 моделей, 333 теста в `tests/api`.

---

## Ничего не сломано

Плоские пути `/v1/search/{global,local,naive}` и их тела не менялись.
`sgr-agent-ragu` продолжает работать без правок — это закреплено тестом
`test_the_flat_paths_older_clients_use_are_untouched`.

Все добавления аддитивны: новые поля опциональны, новые маршруты отдельны,
значения по умолчанию прежние.

---

## Что появилось

| Что | Где | Зачем |
|---|---|---|
| `meta` у каждого источника | `sources[].meta` | Типизированные поля источника: имя и тип сущности, концы и сила связи, документ чанка, заголовок отчёта. Форма выбирается по `kind`. Убирает точечный запрос за метаданными на каждый источник |
| `source_chunk_ids` | `EntityItem`, `RelationItem`, `meta` | Провенанс: из каких фрагментов извлечена сущность или связь. Обратного индекса в графе нет, восстановить было нечем |
| `title` и `entity_ids` у сообщества | `CommunityItem` | Заголовок вынут из тела отчёта, который RAGU сам же и рендерит; состав — для подсветки на канвасе |
| `GET /v1/graphs/{id}/entities/{eid}` | новый | Одна сущность. Раньше приходилось звать соседей и искать корень в ответе |
| `GET /v1/graphs/{id}/chunks` | новый | Коллекция чанков; была только выдача по одному |
| `?ids=` | `/entities`, `/chunks`, `/communities` | Выборка по списку за один запрос. Потолок 500 — это URL под 20 КБ, больше не влезет |
| `?sort=degree\|name`, `?order=`, `?community_id=` | `/entities` | Сортировка на сервере. Без неё топ-N по связности требовал выкачать корпус |
| `POST /v1/graphs/{id}/relations/select` | новый | Индуцированный подграф: связи внутри набора сущностей. Набор едет телом, потому что 500 идентификаторов в query не помещаются |
| `engines` у `mix` | тело запроса | Состав ансамбля выбирает запрос: `local`, `naive`, `global`. По умолчанию первые два |
| `retrieval_ms`, `generation_ms` | `usage.stages` | Разбивка «поиск против LLM» |
| `RAGU_API_GRAPH_CACHE_MAX_ITEMS` | настройка | Потолок материализации графа в памяти; `0` отключает кеш |

## Что изменило поведение

**Потолок страницы 500 → 5000** у `/entities`, `/relations`, `/communities` и
`/relations/select`. Умолчание осталось **50**, так что existing-клиентов это не
трогает. Исключение: `?ids=` в query-строке остался на 500 — там ограничение не
в сервере, а в длине URL.

**Требования `mix` к графу теперь считаются по составу ансамбля, а не по
режиму.** `["local","naive"]` работает на графе без саммари сообществ;
`["local","global"]` на том же графе отвечает `409` с
`missing_capability: "community_summaries"`.

**Батч сводит отчёт о движках по всем запросам.** Раньше отдавался отчёт первого,
и деградация на седьмом вопросе из двадцати была невидима.

**`engines.rerank_error` наконец заполняется.** Запись терялась в дочерней задаче
`asyncio.gather`: мёртвый реранкер отдавал `null`. Если вы на это поле не
смотрели, потому что оно всегда было пустым, — стоит начать.

## Третья серия: по замечаниям потребителя

| Было | Стало |
|---|---|
| У `RaguClient` не было `entity()`, `chunks()`, `select_relations()`, а у `entities()` — сортировки, фильтра по сообществу и `ids` | Клиент догнал сервис. Тест теперь падает, если у маршрута чтения графа нет метода в клиенте |
| `python -m ragu.api` не строил реранкер: `create_app(reranker=...)` был, а CLI его не передавал | CLI собирает клиента к реранкеру из `RERANKER_BASE_URL` / `RERANKER_MODEL_NAME` / `RERANKER_API_KEY`. Без LLM-ключей по-прежнему стартует и объясняет причину через `/health` |
| У источников `local` не было `score`: у сущностей и связей в трейсе стоял `0.0` | Сущность несёт векторный скор, по которому её нашли; связи, саммари и чанки — скор реранкера. Ядро раньше **выбрасывало** скоры реранкера — теперь хранит их в `metrics["rerank_scores"]`. Где скора нет — `null` |
| Отказ реранкера отдавал `0.0` в скоре | `NaN` внутри, `null` на проводе: ноль выглядел бы как «нерелевантно» |
| Время реранка сидело внутри ретривала | Отдельная стадия `usage.stages.rerank` с `rerank_ms`; `retrieval_ms` его больше не включает |
| Параллельные вызовы модели суммировались: четыре одновременных по секунде давали «4 с генерации» | Время считается по стене, перекрывающиеся интервалы объединяются |
| `GraphDetail` не отдавал дату | `updated_at` — последняя запись в файлы графа. `created_at` — только где ФС его знает: **на Linux это `null`**, а не придуманная дата |
| `import ragu.api.client` — 3 с и ~3400 модулей, включая fastembed, sklearn, pandas, nltk и FastAPI | **0,37 с и 272 модуля**, тяжёлых библиотек ноль. `ragu`, `ragu.search_engine` и `ragu.api` грузят имена лениво; параметры движков вынесены в `ragu.search_engine.params` |

**Что это значит для потребителя.** `_ExtendedClient` и собственный
`ragu_api_service.py` можно удалять. `null` в `score` стоит показывать как «—»,
а не как ноль. Для «собран» в карточке берите `updated_at`: на Linux-развёртывании
`created_at` будет пустым всегда.

**Чего это не решает.** Вес *установки*: `graph-ragu` по-прежнему ставит
fastembed, sklearn и остальное как обязательные зависимости — импорт стал лёгким,
а пакет нет. Чтобы клиент ставился без них, его нужно выделять в отдельный
дистрибутив.

## Четвёртая серия: раскладка пакета

Контракт не менялся: `docs/openapi.json` совпадает байт в байт, тесты те же 318.
Поменялось только то, где лежит код.

| Было | Стало |
|---|---|
| `routes.py`, 1306 строк | `routes/` по тегам OpenAPI: `search`, `graphs`, `browse`, `jobs`, `service`, общее — в `deps` |
| `models.py`, 777 строк | `models/`: `common`, `search`, `sources`, `graphs`, `jobs`, `service` |
| `backends/ragu_backend.py`, 1190 строк | `backends/ragu_backend/`: `backend`, `graph_view`, `engines`, `ingest`, `settings` |
| `backends/base.py`, 668 строк | `base.py` — только интерфейс; требования режимов и `GraphStats` — в `capabilities.py` |
| 18 модулей в корне пакета | `search/` — mapping, reranking, usage; `runtime/` — middleware, auth, jobs, registry, metrics, request_context, logging_setup |
| `tests/api/test_api.py`, 4356 строк | 16 модулей по той же схеме, общие помощники — в `support.py` |

**Потребителю менять нечего.** `ragu.api`, `ragu.api.client`, `ragu.api.models`,
`ragu.api.app`, `ragu.api.config`, `ragu.api.backends` и
`from ragu.api.backends.ragu_backend import RaguBackend` работают как раньше.
`ragu.api.models` теперь ещё и реэкспортирует параметры движков (`LocalParams` и
остальные), чтобы запрос собирался из одного импорта.

**Тому, кто дорабатывает.** Внутренние модули переехали без шимов:
`ragu.api.mapping` → `ragu.api.search.mapping`, `ragu.api.usage` →
`ragu.api.search.usage`, `ragu.api.middleware` → `ragu.api.runtime.middleware` и
так далее. Чтение графа теперь у `GraphView`: кеши узлов, рёбер и степеней — его
состояние (`backend.view`), а не бэкенда. Полная карта — в `ragu/api/README.md`,
раздел «Package layout».

## Пятая серия: бюджет до вызова, а не после

| Было | Стало |
|---|---|
| Бюджет сверялся, когда ответы уже вернулись. Батч уходил целиком: global с 474 сообществами при лимите 12 оплачивал все 474 вызова и только потом получал `429` | Вызов учитывается при отправке: вызов или батч, который не помещается, отклоняется до отправки. Global считает свои вызовы ещё до первого — `GlobalSearchEngine.planned_calls()` — и получает `429` бесплатно |
| Проход global, который помещался впритык, оплачивался целиком, а отказ приходил на ответе после него | План считает и проход, и ответы — отказ до первого вызова |
| В потоке отказ бюджета приходил событием `error` с кодом `INTERNAL_ERROR` | Global проверяется до открытия потока — честный `429`; отказ, случившийся внутри потока, приходит событием `error` со своим кодом |
| Поток, брошенный клиентом, в `usage.calls` не попадал | Вызов учитывается при отправке, брошен поток или нет |
| `429` не был описан в OpenAPI поисковых маршрутов | Описан: `BUDGET_EXCEEDED` и `TOO_MANY_REQUESTS` |

Бюджет по-прежнему выключен по умолчанию, и без него ничего не считается —
лишнего чтения хранилищ нет. Токены ответа известны только после ответа: если
они вывели запрос за лимит токенов, остановится следующий вызов.

## Что можно удалить у себя

- кеш всех связей и фильтрацию индуцированного подграфа на клиенте;
- точечные запросы за метаданными источников;
- парсинг `Report title:` регуляркой из текста саммари;
- собственный замер времени «поиск против генерации» — теперь ещё и с реранком отдельно;
- `_ExtendedClient` поверх приватных методов `RaguClient`;
- собственный скрипт запуска сервиса ради реранкера;
- конструирование движков и определение возможностей корпуса — есть
  `GET /v1/graphs/{id}/capabilities`.

---

## О чём помнить

**Два разных `429`.** `TOO_MANY_REQUESTS` — повторять с паузой.
`BUDGET_EXCEEDED` — повтор даст тот же отказ: запрос не помещается в бюджет, и
помогает только менять сам запрос — например, поднять `min_cluster_size`. Сам
отказ бесплатный: он приходит до того, как ушёл первый лишний вызов.

**Два разных `409`.** Названная `missing_capability` — хранилища нет, режим
здесь не заработает никогда. `null` — хранилище есть, но этот запрос ничего не
извлёк, стоит переформулировать.

**Ключ API.** `RAGU_API_API_KEYS` пуст по умолчанию, и тогда сервис отвечает
всем. Для любого развёртывания дальше localhost нужен заголовок `X-API-Key`
или `Authorization: Bearer`.

**Таймауты должны сходиться.** У сервиса `RAGU_API_REQUEST_TIMEOUT` = 300 с.
Клиентский больше — отвалится сервер и придёт `504`; меньше — запрос будет
брошен уже оплаченным.

---

## Чего по-прежнему нет

| | Почему |
|---|---|
| Сессии, история диалога | Каждый запрос независим; повторный поиск внутри одной цепочки оплачивается заново |
| Несколько реплик | `Settings` — процессный синглтон, файловые хранилища не терпят параллельного доступа |
| Задания после перезапуска | `JobStore` — интерфейс, реализация одна, в памяти |
| `level` / `cluster_id` у источников `global` | `GlobalSearchResult` хранит инсайт *о* сообществе и не говорит, о каком. Заполнен только `title` |
| Точные токены | Считаются локально токенизатором, помечены `estimated: true`. Для бюджета годятся, для счёта нет |

## Схема

```bash
python -m ragu.api --dump-openapi docs/openapi.json   # после правки контракта
```

`tests/api` сверяет [`../openapi.json`](../openapi.json) с работающим
приложением и падает с этой же командой, если они разошлись. Клиента можно
сгенерировать из файла, не поднимая сервис.
